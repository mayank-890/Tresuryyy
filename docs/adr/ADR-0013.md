# ADR-0013: Partitioned projection unique keys include event_time

- Status: Accepted
- Date: 2026-10-29
- Deciders: operator

## Context

PostgreSQL range-partitioned tables require any `UNIQUE` or `PRIMARY KEY` constraint on the parent table to include all partition-key columns. Projected append tables (`market_ticks`, `candles_1m`, `order_events`, `fills`, `position_snapshots`, `risk_events`, `audit_log`) partition on `event_time`.

TECHNICAL_IMPLEMENTATION.md §11.1 originally specified `(source_segment, source_sequence)` for all projected tables. That pair alone cannot be enforced as a unique constraint on the partitioned parent in PostgreSQL 16.

Journal replays must remain idempotent: projecting the same record twice must not create duplicate rows. The journal header `wall_ns` field (DESIGN §10.1) is fixed per record, so including `event_time` derived from `wall_ns` does not weaken idempotency.

## Decision

- Non-partitioned projected tables keep `UNIQUE (source_segment, source_sequence)`.
- Partitioned append tables use `UNIQUE (source_segment, source_sequence, event_time)`.
- `event_time` is always `timestamptz` from the journal header `wall_ns` (UTC), never `now()` or wall-clock at insert time.
- Projector inserts use `ON CONFLICT DO NOTHING` on the matching unique constraint for each table.

## Consequences

- Positive: Migrations apply cleanly; replay idempotency preserved; partition pruning unchanged.
- Negative: Projector and SQL must reference three columns on conflict for partitioned tables; documentation must stay aligned with DESIGN §11.
- Follow-up tickets: Phase 1 projector implementation must implement `wall_ns` → `event_time` mapping and conflict targets per table.

## Alternatives considered

- Per-partition unique indexes only — rejected: operational burden and no parent-level guarantee.
- Defer partitioning until a later phase — rejected: retention and volume requirements in DESIGN §11.
- Partition by `source_segment` — rejected: conflicts with time-based retention and query patterns.
