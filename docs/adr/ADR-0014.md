# ADR-0014: Config parsing and promotion signature dependencies

- Status: Proposed
- Date: 2026-10-29
- Deciders: operator

## Context

T-0007 requires TOML profile parsing, JSON Schema validation of profile structure, SHA-256 profile content hashing, and Ed25519 promotion-file signature verification (DESIGN §13.2, TI §8). `vcpkg.json` currently lists only GoogleTest. Hand-rolled TOML or cryptography is forbidden.

OpenSSL is on the TI §7.1 allowlist (Accepted). `nlohmann-json` and a TOML library are listed as Proposed for config use.

## Decision

Add to `vcpkg.json` and link the engine config module and `trader`:

| Package | Purpose |
|---|---|
| `tomlplusplus` | Parse `config/profiles/*.toml` |
| `nlohmann-json` | Load `config/schema/*.json`; promotion file JSON; canonical hash input |
| `openssl` | SHA-256; Ed25519 sign/verify for promotion files in tests and verifier |

Profile validation implements the subset of JSON Schema needed for `profile.schema.json` (required fields, types, `additionalProperties: false`).

## Consequences

- Positive: Standards-based parsing and verification; promotion tests generate ephemeral keys at runtime.
- Negative: Larger binary; OpenSSL linkage; dependency pins must stay in sync with vcpkg baseline.
- Follow-up tickets: Wire config hash to journal writer when journal persistence lands (TC-CF-07 full path).

## Alternatives considered

- Python validator invoked from `trader` — rejected: adds runtime coupling; C++ startup path should stay self-contained.
- Minimal custom TOML subset parser — rejected: ticket forbids hand-rolled parser.
- libsodium instead of OpenSSL for Ed25519 — rejected: OpenSSL already allowlisted for TLS and crypto.
