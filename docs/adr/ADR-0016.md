# ADR-0016: Python `websockets` for Delta public feed capture (T-0106)

- Status: Accepted
- Date: 2026-10-30
- Deciders: operator
- Accepted by operator on 2026-10-30

## Context

Phase 1 ticket **T-0106** requires live (and test-double) **Delta Exchange public WebSocket** tick capture into the rotating journal (`RotatingJournalWriter`, T-0105). Recording runs in **`services/src/tradelab_services/ingestion/`** (Python 3.12), which already uses a mock NDJSON feed in CI and does not import broker or order code.

AGENTS.md §3 forbids adding dependencies without an **Accepted** ADR. TECHNICAL_IMPLEMENTATION.md lists **Boost.Beast** for the C++ engine as **Proposed** only; the T-0106 recording path is **not** on the engine order hot path.

Related operator questions (safe defaults until answered):

- **Q-16:** Live symbol list and `instrument_id` map — default **empty list** → ingestion refuses live connect (no symbols subscribed).
- **Q-18:** Delta public feed licensing — **TODO(operator)**; no continuous live capture in production until confirmed.

## Decision

Add the **`websockets`** PyPI package (asyncio WebSocket client/server library, BSD-3-Clause) to the **research uv project** dependency set used by `just services-test` / ingestion CLI:

- Used **only** from `tradelab_services.ingestion` for Delta public WS connect, subscribe, read frames, reconnect with backoff, and shutdown.
- **Not** imported from the C++ engine, control API, UI, or any order/risk module.
- CI and default `just check` use **mock WebSocket** tests (in-process or scripted frames); **no live network** required in CI.
- Pin version in `research/pyproject.toml` and refresh `research/uv.lock`.

Reconnect policy (align with TI §11): exponential backoff, base 1 s, cap 60 s, jitter ±20%; record feed health / gaps via existing ingestion health helpers.

## Consequences

- Positive: Mature asyncio WS client; fits Python recorder; easy mock/replay testing.
- Negative: New dependency and lockfile churn; asyncio lifecycle must not block clean journal flush on shutdown.
- Follow-up: Operator supplies instrument list (Q-16) and licensing sign-off (Q-18) for production live capture.

## Alternatives considered

- **Boost.Beast (C++ in `engine/src/marketdata/`)** — rejected for T-0106 primary path: recording journal writer is Python-side; Beast remains Proposed for engine private feeds in later phases.
- **`websocket-client` (sync)** — rejected: poor fit for concurrent health/stale checks and graceful shutdown with asyncio ingestion loop.
- **aiohttp ClientSession.ws** — rejected: heavier dependency; `websockets` is sufficient for public feed only.
- **stdlib only** — rejected: no stable stdlib WebSocket client in Python 3.12 for production reconnect semantics.
