# ADR-0015: pyarrow for research Parquet I/O (T-0101)

- Status: Proposed
- Date: 2026-10-29
- Deciders: operator

## Context

Phase 1 ticket **T-0101** requires historical OHLCV ingestion into **Parquet** under the external data root, with data-quality checks and fixture-based tests. The research package (`research/`) is the designated offline analytics and ingestion surface (REPO_STRUCTURE.md; TI §7.1 lists **pyarrow** under Python data as Accepted at the stack level).

No pyarrow dependency is pinned in `research/pyproject.toml` today. AGENTS.md §3 requires an ADR and operator approval before adding dependencies. Blocker **B-0101-3** tracks this gap.

## Decision

Add **pyarrow** (Apache Arrow Python bindings) to the **research** uv project only, for:

- Writing normalized OHLCV Parquet datasets under the operator-configured external data root (not under the git repo).
- Reading Parquet in unit/integration tests via fixtures under `tests/fixtures/` or research test helpers.

Constraints:

- **Not** on the C++ engine hot path; **not** imported from `services/` projector or control API in T-0101.
- Pin version in `research/pyproject.toml` and `research/uv.lock` after this ADR is **Accepted**.
- No `pickle` for persisted or transmitted data (TI §4.2).

## Consequences

- Positive: Standard columnar format; aligns with TI Python data stack; enables T-0101 acceptance criteria.
- Negative: Larger research venv; native wheels platform matrix; license review (Apache 2.0).
- Follow-up: Operator confirms [Delta Exchange terms](https://www.delta.exchange/legal/terms-of-use) for historical data storage (recorded in PROGRESS T-0101).

## Alternatives considered

- **polars only** — rejected for T-0101: Parquet write/read is explicitly required; polars may sit on pyarrow but does not remove the need for a clear Parquet dependency choice.
- **Custom binary files** — rejected: conflicts with T-0101 and REPO_STRUCTURE external Parquet layout.
- **pyarrow in services/** — rejected: keep ingestion CLI in research/ for Phase 1; projector remains journal-driven.
